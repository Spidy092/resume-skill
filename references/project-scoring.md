# Project selection

Projects earn space by proving target-role capability that work history does not already prove strongly.

Each project records 0–5 ratings for `impact`, `complexity`, `production`, and `verifiability`, plus skills, outcomes, dates, and evidence IDs. Ratings require notes; do not guess them from repository size or popularity.

## Baseline score

```text
35% target-skill relevance
20% impact
15% technical complexity
15% production use
10% verifiability
 5% uniqueness against already selected evidence
```

Normalize ratings to 0–1. Prefer recent projects when relevance and evidence strength are close. Penalize tutorial clones, unfinished demonstrations, and duplication of stronger employment evidence. Do not infer personal ownership from repository ownership or production usage from deployment configuration alone.

Select the smallest set that proves the most important unmet requirements, normally two or three. A lower-scoring project may be selected when it uniquely proves a mandatory requirement; state the reason.
